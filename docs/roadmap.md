# Maa-Web · 开发路线图（Roadmap）

> 版本：v0.3.0 ｜ 更新日期：2026-08-14
> 本路线图依据 [PRD](./PRD.md) 功能表（客户端源码核对版）逐项拆解，按「引擎就绪 → 日常任务 → 高级玩法 → 工具箱 → 调度与系统 → NAS 发布」六层推进，保证 MAA 桌面端全部功能进入开发规划。
> 前端实现遵循 [UI 设计规范](../ui-design/design-system-arknights.md)（明日方舟主题），每阶段验收同时核对 [组件画廊](../ui-design/07-component-gallery.html) 控件语义。

---

## 0. 总览

```
M1 ▸ 脚手架 + Docker 化（已完成）
M2 ▸ 引擎接入 + 设备管理（已完成，剩 Custom 实机验证）
M3 ▸ 日常任务模块（表单/队列已就绪，真机验收中）
M4 ▸ 高级玩法模块（作业站集成完成，执行验收待排期）
M5 ▸ 工具箱模块（六项识别工具）
M6 ▸ 调度与系统功能（定时/通知已提前落地；配置管理已裁）
M7 ▸ NAS 优化 + 发布 v1.0
```

依赖关系：M2 是 M3~M5 的地基；M3/M4 可部分并行；M6 依赖 M3 的日志与 M2 的任务队列；M7 收尾。

> **已落地（2026-08-14 核对）**：C-01~C-03、D-01、D-02、S-05、S-07、引擎层全部实现并在真机（Redmi K30 USB）实测通过：
> - S-07 支持 **GitHub / Mirror酱（MirrorChyan）双更新源**：设置页切换更新源、ghproxy 镜像前缀、MirrorChyan CDK 有效期检查（`cdk_expired_time`，错误码 7001/7002 等对齐 MAA 客户端）；MirrorChyan 走 OTA 增量包（`changes.json` deleted + 覆盖，防路径穿越），GitHub 源走整包原子替换

> - C-01 附「分辨率预检与调整」：MAA 仅支持 16:9 / 9:16（≥720p），任务启动前预检（`taskrunner._ensure_resolution_supported`），设备页可查询/设置/重置 `wm size`（真机竖屏 1080x1920 / 模拟器 1920x1080）
> - D-09 Copilot 作业站（prts.plus）后端集成已随本阶段落地：`copilot_mgr.py` 解析 `prts://99359` / `prts://s51251` / `s51251` / `maa://` 代码，拉取单个作业/作业集保存至 `resource/copilot/`，任务参数面板支持多作业勾选（见 M4）

### 关键设计

- 后端 `AsstProxy` ctypes 直调 MaaCore（官方发布包内的 `MaaCore.dll` / `libMaaCore.so`）：连接设备 → `AsstAppendTask(type, params) × N` → `AsstStart`（非阻塞）→ 订阅回调（`AsstMsg`：TaskChain*/AllTasksCompleted）→ WS 推送。
- 引擎切换背景（2026-08）：MaaFw 5.x 的 `Resource.post_pipeline` 只接受 Pipeline v2 格式，无法加载 MAA 官方资源（自研旧格式 + MaaCore 私有识别器），故引擎切换为 MAA 官方 Asst 核心（与桌面客户端同引擎）。
- 任务运行状态机：`idle → running → finished/error/stopped`。
- 会话隔离：每个设备独立 Asst 实例，停止/断开时安全销毁。
- 资源包：`POST /api/v1/resources/update` 下载完整发布包（win zip / linux tar.gz），校验 `resource/` + 引擎库后原子替换 `maa_resource_dir`。

### 关键设计

- 前端任务编排：**作战总览（/）与任务编排（/tasks）复用同一套任务类型与参数 UI 组件**（`frontend/src/tasks/`）。作战总览为高频「每日」快速路径（队列改动即时保存到 localStorage，刷新/切页不丢）；任务编排为精细自动化（方案「任务文件」模式：为当前配置命名保存，之后随时调出复用），两页均可启动/停止队列。
- 基建自定义排班：实现 MAA「基建排班协议」JSON 的解析与可视化编辑（二期可视化，一期支持导入）。
- 掉落数据上传：企鹅物流 / 一图流 ID 配置 + 上报开关。
- 数据更新/仓库保持：依赖 D-12 更新的仓库数据判断库存，多 Plan 独立执行。

> **已落地（2026-08-14 核对）**：S-01 任务编排 v1（拖拽排序/勾选启用/仅一次/LINK START/STOP/方案保存）与 D-03~D-07 全部任务类型（Fight/Recruit/Infrast/Mall/Award）的前端参数表单 + 后端任务映射 + 队列下发通道已实现（`frontend/src/tasks/forms/`、`asstproxy.to_asst_task()`），字段对齐 MAA 客户端源码模型；真机实测过 StartUp（D-01），其余任务类型待逐项实机执行验收。
